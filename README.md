# ネットワーク死活監視Webダッシュボード (Network Ping Monitor)

同一ネットワーク内に接続された最大100台までのネットワーク機器（ルーター、サーバー、変調器、端末等）に対し、定期的にPing疎通確認を行い、応答がない場合に複数のWebhook（Slack、Google Chat等）へ障害アラート・復旧アラートを即座に通知するNode.js製Webアプリケーションです。

---

## 1. アプリケーション概要 & 特徴

### クロスプラットフォーム完全対応

macOS / Linux（AlmaLinux、Ubuntu等）/ Windows に対応しています。

OSごとの `ping` コマンド引数・単位差分や、結果テキスト（`TTL=`、`bytes from` 等）をバックエンドで自動判別・解析します。

### 100台規模対応の軽量設計

10台ごとのバッチ分割並列処理（`Promise.all`）を採用しています。

これにより、プロセスの乱立によるCPUスパイクやメモリ圧迫を防止します。

### 2つの監視方式（完全排他制御）

以下の2種類の監視方式に対応しています。

#### ① 指定時刻セット監視

カレンダーで指定した日時を起点に、「毎日」または「一度だけ」の一斉疎通確認を実行します。

#### ② ms周期監視

ミリ秒単位で指定した間隔で自動巡回します。

例：

```text
30000ms = 30秒
100000ms = 100秒
```

> **監視方式は完全排他です。**
>
> どちらか一方が選択されている間、もう片方のタイマー処理はバックエンドで完全に停止します。

### 操作性と視覚的UX

- ライト調テーマUI
- 開閉可能なアコーディオンパネル構造
- 機器一覧のドラッグ＆ドロップによる自由な並び替え
- 並び順の自動保存
- 機器ごとの個別Pingタイムアウト設定
- 機器ごとの個別Pingリトライ回数設定
- 機器ごとの個別Webhook通知先設定
- 任意IPに対する即時疎通テスト
- 登録機器に対する即時疎通テスト
- 設定入力中の自動ポーリングによる画面チラつき・入力値リセット防止
- `isEditingSettings` による設定編集中の状態制御

## 3. 使い方

## 3.1. 監視対象機器の管理

### 機器の追加

画面左上の「＋ 機器を追加」ボタンを押すと、機器追加用のモーダルが開きます。

1. **機器名（Label）**を入力します。
2. **IPアドレス**を入力します。
3. 「保存」ボタンを押します。

### 有効 / 無効の切り替え

各機器行にあるトグルスイッチ（`.switch-label`）を押すことで、監視の有効 / 無効を即座に切り替えられます。

- **有効**：自動巡回の対象になります。
- **無効**：自動巡回からスキップされます。

### 並び順の変更（ドラッグ＆ドロップ）

行の左端にあるグリップアイコン（⋮⋮）をつかみ、上下にドラッグ＆ドロップすることで機器の並び順を変更できます。

変更した並び順は、バックエンドの `config.json` に即座に自動保存されます。

### 機器の編集 / 削除

各機器の操作セルから以下の操作ができます。

- **編集**：「編集」ボタンを押すと設定モーダルが開きます。
- **削除**：「削除」ボタンを押すと監視対象から除外されます。

---

## 3.2. 監視方式の選択と切り替え

右側パネルの「⚙ 監視方式・パラメータ設定」内にあるカードタブから、監視方式を選択します。

### ① 指定時刻セット監視

カレンダーから日時（`YYYY-MM-DDTHH:mm`）を選択し、繰り返し種別を指定して「追加」ボタンを押します。

#### 毎日

指定した日時が巡回開始の起点日となります。

起点日以降、毎日指定した時刻に疎通確認を実行します。

#### 一度だけ

指定した日時に一度だけ疎通確認を実行します。

### ② ms周期監視

一定間隔で監視を実行する方式です。

監視周期をミリ秒単位で入力します。

| 設定値 | 実行間隔 |
|---:|---|
| `30000` | 30秒ごと |
| `100000` | 100秒ごと |

### 設定の適用

画面下部の「基本設定を保存」ボタンを押すと、バックエンドのスケジューラーが即座に再起動され、新しい監視方式が適用されます。

---

## 3.3. 個別Pingパラメーターの設定（オーバーライド）

特定の機器だけレスポンスが遅い場合や、リトライ回数を増やしたい場合は、機器ごとにPing設定を上書きできます。

### 設定手順

1. 対象機器の「編集」ボタンを押します。
2. 機器の追加時は、追加モーダルを開きます。
3. 「個別のPing設定を行う」にチェックを入れます。
4. 以下の項目を入力します。
   - 個別タイムアウト（ms）
   - 個別リトライ回数
5. 保存します。

設定後、テーブル一覧のPing設定欄には以下のように表示されます。

```text
個別 (3000ms / R:4)
```

個別設定が指定されている場合は、**全体設定よりも個別設定が優先して適用されます。**

---

## 3.4. 複数Webhook通知の仕様

### 標準通知先

「⚙ 監視方式・パラメータ設定」の「標準 Webhook URL」に、複数のWebhook URLを改行区切りで入力できます。

Slack、Google Chatなど複数の通知先を設定した場合、全機器の障害・復旧通知が設定されたすべてのURLへ一斉送信されます。

例：

```text
https://example.com/webhook/slack
https://example.com/webhook/google-chat
```

### 個別通知先

機器編集モーダルで「個別 Webhook URL」を設定すると、その機器の障害・復旧通知のみを個別URLへ送信できます。

個別Webhook URLが未設定の場合は、**標準Webhook URL**が使用されます。

### 通知タイミング

通知は、機器の状態が変化した場合のみ送信されます。

| 状態変化 | 通知 |
|---|---|
| UP → DOWN | 障害通知 |
| DOWN → UP | 復旧通知 |
| UP → UP | 通知なし |
| DOWN → DOWN | 通知なし |

これにより、障害発生中の不要な連続通知を防止します。

---

## 3.5. 即時Pingテストツールの活用

右側パネルの「⚡ 即時Pingテストツール」から、任意のIPアドレスに対して即時Pingテストを実行できます。

### 任意のIPをテスト

1. テスト対象のIPアドレスを入力します。
2. タイムアウト（ms）を入力します。
3. 「テスト送信」ボタンを押します。

登録されていないIPアドレスでもテスト可能です。

テスト実行後、Pingの応答時間（ms）が表示されます。

### 登録済み機器をテスト

監視対象機器一覧の操作セルにある **`test`** ボタンを押すと、その機器に対して即座に疎通テストを実行できます。

テストには以下の設定が使用されます。

- 対象機器に設定されているIPアドレス
- 対象機器に設定されているタイムアウト値

---

## 3.6. ログの確認

ダッシュボード右下にある「📜 リアルタイム監視ログ」アコーディオンを開くと、監視ログをリアルタイムで確認できます。

### 表示内容

- 直近 **150行** のログを表示
- リアルタイムでログを更新

### ログファイル

ログの実体は、プロジェクト直下の以下のファイルにテキスト形式で保存されます。

```text
log/monitor.log
```
